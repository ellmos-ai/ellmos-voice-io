2. TARGET PERSONAS & USER JOURNEYS
================================================================================
1. Autonomous Local AI Agent Developers & Multi-Agent Swarm Orchestrators
   - Needs: Add voice input (STT), voice synthesis (TTS), and hands-free wake-word detection to autonomous agent workflows (Claude Code, Antigravity, Codex, Kimi, n8n) without introducing heavy daemon runtimes or external cloud API costs.
   - Pain Points: Traditional speech packages enforce deep dependency trees (PyTorch, heavyweight CUDA frameworks) or default to cloud streaming with latency and recurring token costs.
   - Solution: Modular, lazy-loaded engine architecture. The base package installs in milliseconds with zero dependencies; engines load only when invoked; caller retains full lifecycle control over audio buffers and stop events.

2. Privacy-Conscious Desktop Application Engineers (PySide6 / PyQt / Tkinter / Electron)
   - Needs: Build desktop software requiring accessibility voice output or local audio transcription that runs 100% offline on end-user machines.
   - Pain Points: Cloud STT/TTS APIs violate customer confidentiality and GDPR requirements; users refuse apps that require constant Internet connectivity or telemetry.
   - Solution: 100% Local-First & Zero-Egress (`INV-LOCAL-01`). Supports Vosk for completely offline STT without GPU, pyttsx3 for zero-download native OS voices, and Piper for high-quality local neural synthesis.

3. Edge & Embedded AI Engineers (Raspberry Pi / Mini-PCs / Air-Gapped Kiosks)
   - Needs: Run wake-word listeners and speech synthesis on low-power, headless, or strictly air-gapped industrial devices.
   - Pain Points: Complex background audio daemons hang, fail to release ALSA/PulseAudio/PortAudio devices, or leak memory over long runtimes.
   - Solution: Deterministic microphone lifecycle (`INV-MIC-04`). Synchronous, caller-owned `WakeWordListener.listen()` execution with deterministic hardware cleanup in `finally` blocks and immediate exit on stop events.

4. Enterprise Security, Privacy & Healthcare Compliance Officers
   - Needs: Verify that internal software handling spoken audio or clinical dictation strictly prevents acoustic data leakage, cloud retention, or model training on private conversations.
   - Pain Points: Cloud voice vendors often retain audio logs for "service improvement"; unclear licensing and copyleft contamination risks in open-source audio wrappers.
   - Solution: Caller-owned audio retention (`INV-DATA-05`), explicit copyleft isolation in `THIRD_PARTY_LICENSES.md` (identifying GPL Piper boundaries), unprivileged `RunAsInvoker` execution (`INV-PRIV-02`), and formal 48h security SLA (`INV-SLA-10`).

5. GOVERNANCE & RUNTIME INVARIANTS
================================================================================
- INV-LOCAL-01: 100% Local-First & Zero-Egress (no remote telemetry, no background upload, no cloud endpoints).
- INV-PRIV-02: Non-Elevation / RunAsInvoker (runs entirely with standard user privileges; never requests UAC elevation).
- INV-OPTIN-03: Explicit Model Download Consent (mandatory caller opt-in for Whisper downloads; local files default).
- INV-MIC-04: Deterministic Microphone Lifecycle (hardware stream engaged only during active listen; closed in `finally`).
- INV-DATA-05: Caller-Owned Audio Retention (zero internal audio file retention, caching, or telemetry logging).
- INV-LAZY-06: Lazy Engine Isolation (unimported optional engines consume zero RAM and trigger zero side-effects).
- INV-CLI-07: Read-Only Inspection CLI (`ellmos-voice-io status` inspects via `find_spec` without hardware allocation).
- INV-PORT-08: Cross-Platform Operating Parity (verified on Windows, Linux, macOS across Python 3.10-3.13).
- INV-SYNC-09: Cloud-Sync & Multi-Agent Defense (.gitignore protects against `LOCK.*`, conflict files, and sync artifacts).
- INV-SLA-10: 48h Security SLA & Coordinated Disclosure (formal vulnerability reporting with 48h response commitment).
